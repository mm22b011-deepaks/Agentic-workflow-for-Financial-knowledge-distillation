4b. WHY THE PREVIOUS MUTATION RUNS REPORTED LEFTOVER EDITS
---------------------------------------------------------
Two mutation runs were started in parallel with the ordinary test suite and with each
other. Each one writes a mutant into a source file and restores it in a `finally`; two
runs writing different mutants into the same file means whichever finishes first restores
its own copy over the other's edit, so the tree could hold a mutant and appear "unclean".
Symptom: three tests failing in `review_queue` / `units` / `runner` with no source change
of mine. Recovery: `grep -rn "if False:" src/` and each mutant's exact text, then restore
the line; `git diff` confirms nothing else changed. Lesson, now a standing rule: the
mutation check runs alone. Its own sha256 guard catches a corrupted restore, but it cannot
catch a second process.
